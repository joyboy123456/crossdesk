# CrossDesk 跨设备键鼠共享工具 PRD

> 文档版本：V1.0
> 项目代号：CrossDesk
> 技术基线：Lan Mouse Fork
> 目标平台：Windows 10/11、macOS 13+
> 主要开发语言：Rust
> 文档用途：供 Claude Code 进行仓库分析、架构设计、任务拆解、编码实现与验收

---

## 1. 项目背景

用户的桌面上同时存在一台 Windows 电脑和一台 Mac，两台设备各自连接独立显示器，显示器物理位置相邻。

当前用户需要分别使用两套鼠标和键盘控制两台电脑，存在以下问题：

1. 桌面外设数量多，占用空间。
2. 在 Windows 和 Mac 之间切换操作时，需要移动双手或切换设备。
3. 多设备工作流不连续。
4. 复制文本、代码和命令时需要借助聊天软件、云剪贴板或其他中间工具。
5. 商业软件可定制性较差，无法针对个人工作流优化延迟、键位和切屏逻辑。

本项目希望通过局域网共享鼠标和键盘，使用户能够使用连接在一台电脑上的键鼠，同时控制 Windows 和 Mac。

用户将鼠标移动到当前屏幕边缘后，控制权应自然切换到另一台电脑，体验接近一台主机连接两块显示器。

---

## 2. 产品目标

### 2.1 核心目标

实现一套低延迟、稳定、安全、可观测、可二次开发的跨平台软件 KVM 工具。

用户应能够：

1. 使用一套鼠标和键盘控制 Windows 与 Mac。
2. 通过鼠标越过屏幕边缘切换目标设备。
3. 在目标设备上获得接近本地鼠标的操作体验。
4. 正确使用点击、滚轮、拖拽、快捷键和组合键。
5. 在网络断开或程序异常时快速恢复本机控制权。
6. 查看当前连接状态、网络延迟和输入事件状态。
7. 根据个人习惯调整屏幕位置、切换阈值和键位映射。

### 2.2 项目成功标准

满足以下条件时，MVP 可视为成功：

* Windows 和 Mac 可以在同一局域网内建立加密连接。
* 鼠标可从 Windows 屏幕右边缘进入 Mac。
* 鼠标可从 Mac 屏幕左边缘返回 Windows。
* 移动、点击、拖拽、滚轮和键盘输入正常。
* 不出现按键或鼠标按钮永久卡住的问题。
* 网络断开后，本机键鼠控制可在 1 秒内恢复。
* 有线局域网下，远端输入总延迟 P95 不高于 15ms。
* 普通 5GHz Wi-Fi 下，远端输入总延迟 P95 不高于 30ms。
* 持续使用 4 小时不崩溃、不失去控制权。
* Windows 和 Mac 睡眠唤醒后，可以自动恢复或一键重连。

## 3. 产品定位

CrossDesk 是一个面向开发者和多设备办公用户的跨平台键鼠共享工具。

它不是：

* 远程桌面软件。
* 屏幕投射软件。
* 视频传输工具。
* 云端远程控制工具。
* USB 硬件 KVM 的完全替代品。
* 面向公网暴露的远程运维工具。

CrossDesk 默认只服务于可信局域网中的近距离设备协同。

## 4. 目标用户

### 4.1 第一目标用户

同时使用 Windows 与 Mac 的开发者。

典型场景：

* Windows 用于显卡计算、模型部署或兼容性工作。
* Mac 用于写代码、办公和日常开发。
* 两个显示器并排放置。
* 用户希望只保留一套键鼠。

### 4.2 第二目标用户

同时使用多台电脑的设计师、技术支持工程师、测试人员和内容创作者。

## 5. 默认使用场景

MVP 默认拓扑：

```text
┌──────────────────────┐    ┌──────────────────────┐
│ Windows 显示器        │    │ Mac 显示器            │
│                      │    │                      │
│ 键盘、鼠标物理连接端   │ →  │ 局域网输入接收端       │
└──────────────────────┘    └──────────────────────┘
          左侧                         右侧
```

默认配置：

```text
主设备：Windows
副设备：macOS
Mac 位置：Windows 右侧
连接方式：局域网
优先网络：有线网络
备用网络：5GHz 或 6GHz Wi-Fi
默认切换方式：鼠标越过屏幕边缘
紧急释放快捷键：Ctrl + Alt + Shift + Esc
```

架构必须支持未来交换角色，即 Mac 也可以作为输入发送端。

## 6. 产品范围

## 6.1 MVP 必须实现

### F-01 设备发现与连接

支持以下连接方式：

1. 手动输入 IP 地址。
2. 手动输入主机名。
3. 保存最近连接过的设备。
4. 断线自动重连。
5. 展示设备在线、连接中、已连接、断开和异常状态。

自动发现不是 MVP 强制项，但架构中不得阻碍后续加入 mDNS。

### F-02 设备授权

第一次连接时，接收端必须明确授权发送端。

至少展示：

* 设备名称。
* IP 地址。
* 设备指纹。
* 操作系统。
* 授权或拒绝按钮。

授权结果应持久化保存。

未授权设备不得发送输入事件。

### F-03 屏幕布局配置

MVP 支持四个相对方向：

* Left
* Right
* Top
* Bottom

用户可以指定某设备位于当前设备的哪一侧。

MVP 可以使用表单配置，不强制要求拖拽式屏幕布局编辑器。

配置示例：

```toml
[[clients]]
hostname = "my-mac"
position = "right"
activate_on_startup = true
```

### F-04 鼠标跨屏切换

当鼠标到达已配置的屏幕边缘，并继续向外移动时，将控制权切换至目标设备。

切屏过程中必须满足：

1. 鼠标不能在边缘反复横跳。
2. 切屏后不能立即被误触发切回。
3. 鼠标按下并拖动时可以跨屏。
4. 如果目标设备离线，不得丢失本地鼠标控制权。
5. 切换失败时必须把光标释放回当前设备。

默认参数：

```text
触发边缘宽度：2px
越界累计阈值：6px
切换冷却时间：80ms
目标不可达超时：300ms
```

所有参数必须可配置。

### F-05 鼠标移动

支持：

* 水平移动。
* 垂直移动。
* 斜向移动。
* 多显示器缩放差异。
* 不同分辨率设备之间的映射。
* 相对位移事件。
* 高轮询率鼠标输入。

鼠标移动事件允许合并和丢弃过时事件。

不允许因为网络抖动而继续播放已经过时的鼠标历史轨迹。

### F-06 鼠标按钮

MVP 至少支持：

* 左键。
* 右键。
* 中键。
* 鼠标侧键 1。
* 鼠标侧键 2。
* 双击。
* 长按。
* 拖拽。
* 按住鼠标跨屏。

鼠标按下和松开事件必须可靠、有序传输。

### F-07 滚轮

支持：

* 垂直滚轮。
* 水平滚轮。
* 触控板连续滚动事件。
* Windows 和 macOS 滚轮方向差异配置。
* 滚动倍率配置。

滚轮事件不应与普通鼠标移动使用完全相同的丢弃策略。

### F-08 键盘输入

支持：

* 英文字母。
* 数字。
* 功能键。
* 方向键。
* Delete、Backspace、Home、End。
* Ctrl、Alt、Shift、Win。
* Command、Option、Control、Shift。
* 常用组合键。
* 长按重复输入。
* 多键同时按下。
* 中文输入法环境中的基础键盘输入。

必须区分：

* 物理扫描码。
* 平台键码。
* 逻辑键符号。
* 修饰键状态。

不得直接假设 Windows 键码与 macOS 键码完全一致。

### F-09 键位映射

提供默认映射方案：

```text
Windows Ctrl  → macOS Command
Windows Alt   → macOS Option
Windows Win   → macOS Control
Windows Shift → macOS Shift
```

用户可以选择以下预设：

1. 保持物理键位。
2. 保持语义键位。
3. 自定义键位映射。

“保持语义键位”表示：

```text
Windows 上的 Ctrl + C
进入 Mac 后自动转换为 Command + C
```

自定义映射应使用配置文件保存。

### F-10 紧急释放

必须提供本地紧急释放机制。

默认快捷键：

```text
Ctrl + Alt + Shift + Esc
```

触发后立即：

1. 停止转发输入。
2. 释放鼠标捕获。
3. 将所有远端按键标记为松开。
4. 将所有远端鼠标按钮标记为松开。
5. 恢复本机键盘和鼠标控制。
6. 记录紧急释放日志。

紧急释放必须在本地处理，不依赖网络。

### F-11 断线保护

出现以下情况时，必须主动释放所有输入状态：

* 网络连接中断。
* 对端程序退出。
* 对端电脑睡眠。
* 心跳超时。
* 加密会话失效。
* 本地进程异常关闭。
* 用户手动停止服务。
* 输入注入失败。

不得出现：

* Ctrl 一直处于按下状态。
* Command 一直处于按下状态。
* 鼠标左键一直处于按下状态。
* 本地鼠标无法恢复。
* 光标被永久锁定在屏幕边缘。

### F-12 后台运行

Windows：

* 支持托盘运行。
* 支持开机启动。
* 主窗口关闭后可继续运行。
* 可从托盘暂停或恢复输入共享。

macOS：

* 支持菜单栏运行。
* 支持登录时启动。
* 主窗口关闭后可继续运行。
* 可从菜单栏暂停或恢复输入共享。

### F-13 权限引导

macOS 首次启动时检测：

* 辅助功能权限。
* 输入监控权限。
* 必要的输入捕获或注入权限。

权限缺失时：

1. 不得静默失败。
2. 明确告诉用户缺少什么权限。
3. 提供打开系统设置的入口。
4. 用户返回应用后重新检测权限。
5. 日志中不得把权限错误伪装成网络错误。

Windows 端也需要检测输入捕获与注入是否可用。

### F-14 状态与诊断

主界面或 CLI 至少展示：

* 当前设备名称。
* 当前角色。
* 已连接设备。
* 当前控制目标。
* 网络 RTT。
* 最近心跳时间。
* 输入捕获后端。
* 输入注入后端。
* 当前事件速率。
* 最近错误。

提供“复制诊断信息”功能，自动隐藏敏感信息。

## 8. 非功能需求

## 8.1 延迟目标

在有线千兆局域网环境下：

```text
鼠标移动端到端延迟：
P50 ≤ 6ms
P95 ≤ 15ms
P99 ≤ 30ms

按键端到端延迟：
P50 ≤ 8ms
P95 ≤ 20ms
P99 ≤ 40ms

跨屏切换完成时间：
P95 ≤ 80ms
```

在稳定的 5GHz 或 6GHz Wi-Fi 环境下：

```text
鼠标移动端到端延迟：
P95 ≤ 30ms

跨屏切换完成时间：
P95 ≤ 120ms
```

这里的端到端延迟定义为：

```text
接收到本地操作系统输入事件
→ 事件序列化
→ 网络发送
→ 对端接收
→ 事件反序列化
→ 注入对端操作系统
```

### 8.2 稳定性

* 连续运行 4 小时无崩溃。
* 连续切屏 1000 次无控制权丢失。
* 连续点击 10000 次无按钮状态错误。
* 网络断开并恢复 100 次，无需重启应用。
* 对端强制退出后，本机在 1 秒内恢复。
* 休眠唤醒后 10 秒内自动恢复连接。
* 输入事件队列不得无限增长。

### 8.3 资源占用

空闲状态：

```text
CPU 平均占用 ≤ 1%
内存占用目标 ≤ 150MB
网络流量接近心跳最低需求
```

输入活跃状态：

```text
CPU 平均占用目标 ≤ 5%
不得因为高轮询率鼠标导致单核长期满载
```

### 8.4 安全性

必须满足：

1. 所有输入事件通过加密会话传输。
2. 首次连接需要人工授权。
3. 通过设备指纹识别已授权设备。
4. 默认只监听局域网接口。
5. 未授权设备无法注入输入。
6. 不记录用户实际输入文本。
7. 日志只记录键位类别和事件状态，不记录敏感内容。
8. 配置文件不得明文保存私钥。
9. 不允许静默接受未知设备。
10. 协议必须校验消息长度和事件类型。
11. 对异常频率输入执行限流。
12. 对重复序号、过期事件和非法状态执行丢弃。

## 10. 输入事件模型

### 10.1 事件分类

事件分为三种可靠性等级。

#### A 类：必须可靠、有序

```text
KeyDown
KeyUp
MouseButtonDown
MouseButtonUp
FocusEnter
FocusLeave
ReleaseAll
DeviceSwitch
```

A 类事件不得因为队列拥塞被丢弃。

#### B 类：可合并但需要保留语义

```text
ScrollVertical
ScrollHorizontal
ModifierState
```

连续滚动事件可以合并累计值，但不得改变方向和时序语义。

#### C 类：允许丢弃历史事件

```text
PointerMotion
```

鼠标移动事件采用 latest-event-wins 或累计相对位移策略。

### 10.2 推荐事件结构

具体结构需要结合现有仓库实现确定，逻辑上至少包含：

```rust
pub struct EventEnvelope {
    pub protocol_version: u16,
    pub session_id: u64,
    pub sequence: u64,
    pub capture_timestamp_us: u64,
    pub event: InputEvent,
}
```

输入事件示意：

```rust
pub enum InputEvent {
    PointerMotion {
        dx: i32,
        dy: i32,
    },
    MouseButton {
        button: MouseButton,
        state: ButtonState,
    },
    Scroll {
        horizontal: f64,
        vertical: f64,
    },
    Key {
        physical_key: PhysicalKey,
        state: KeyState,
        modifiers: ModifierState,
    },
    ReleaseAll,
}
```

这只是产品侧推荐结构。

Claude Code 必须先检查当前项目中的事件模型，不得无条件照抄并造成协议重复。

## 11. 鼠标移动队列策略

鼠标移动事件不能与按键事件共用简单 FIFO 队列。

### 11.1 目标

避免网络抖动时出现：

* 鼠标延迟越来越大。
* 鼠标继续补历史轨迹。
* 光标在用户停止移动后仍然移动。
* 高频鼠标导致按键事件排队。

### 11.2 推荐策略

为不同事件类型设置独立逻辑：

```text
PointerMotion:
保留最新位置或累计最新相对位移
队列中最多保留 1～2 个待发送移动事件

Key/Button:
可靠、有序、不得覆盖

Scroll:
在极短时间窗口内合并累计
```

推荐发送循环：

```text
1. 先发送待处理的按钮和键盘状态变化。
2. 再发送滚轮事件。
3. 最后发送最新鼠标移动。
4. 每个循环限制最大事件处理量。
5. 不允许任何队列无限增长。
```

### 11.3 序号处理

接收端需要：

* 丢弃重复事件。
* 识别乱序事件。
* 丢弃过期鼠标移动。
* 不得随意丢弃 KeyUp 和 ButtonUp。
* 在检测到序列缺口时校验当前按键状态。
* 必要时请求一次完整状态同步。

## 12. 输入状态同步

仅转发增量事件不足以保证可靠性。

双方都应维护当前输入状态：

```rust
pub struct InputState {
    pub pressed_keys: HashSet<PhysicalKey>,
    pub pressed_buttons: HashSet<MouseButton>,
    pub modifiers: ModifierState,
}
```

以下时机发送完整状态同步：

* 完成连接。
* 完成设备切换。
* 检测到序列缺口。
* 网络恢复。
* 对端请求同步。
* 定时低频校验。
* 睡眠唤醒。
* 权限恢复。

如果状态不一致，以安全释放为优先，而不是继续保持按下。

## 13. 屏幕边缘与切换状态机

### 13.1 状态定义

```text
Local
EdgePending
Switching
Remote
Returning
Recovering
```

### 13.2 Local

鼠标在本机正常移动。

达到已配置边缘时进入 `EdgePending`。

### 13.3 EdgePending

累计向外位移。

满足阈值后尝试切换。

如果用户向反方向移动，则返回 `Local`。

### 13.4 Switching

执行：

1. 检查目标在线状态。
2. 发送 FocusEnter 或 DeviceSwitch。
3. 等待目标确认。
4. 成功后开始远端转发。
5. 超时则恢复本地鼠标。

### 13.5 Remote

本地输入被捕获并转发至远端。

本地紧急释放快捷键始终有效。

远端返回边缘事件时进入 `Returning`。

### 13.6 Returning

同步按键和鼠标按钮状态。

释放远端控制。

恢复本地光标位置。

进入短暂冷却期。

### 13.7 Recovering

用于处理：

* 网络断开。
* 对端异常退出。
* 注入失败。
* 权限丢失。
* 心跳超时。

处理顺序：

```text
停止发送新事件
→ 本地解除捕获
→ 尝试向远端发送 ReleaseAll
→ 本地清空远端状态缓存
→ 恢复本机控制
→ 进入重连流程
```

## 14. 坐标与屏幕映射

MVP 优先使用相对位移。

跨屏时需要计算进入位置。

例如 Windows 屏幕右侧进入 Mac 左侧：

```text
source_ratio = source_cursor_y / source_screen_height
target_y = source_ratio * target_screen_height
target_x = target_screen_left + entry_offset
```

需要考虑：

* Windows 显示缩放。
* macOS Retina 缩放。
* 逻辑像素与物理像素。
* 菜单栏和 Dock。
* 多显示器排列。
* 不同屏幕高度。
* 横屏和竖屏。

MVP 可以先支持每台电脑一个主显示器，但数据模型不能把设备和屏幕永久绑定为一对一。

## 16. 网络与连接管理

### 16.1 心跳

连接建立后发送心跳。

建议参数：

```text
心跳间隔：500ms
弱连接判断：连续丢失 2 次
断线判断：连续丢失 4 次或超过 2 秒
```

输入转发期间可以复用输入流量作为活跃信号，但不能完全取消心跳。

### 16.2 重连

采用指数退避：

```text
首次：250ms
第二次：500ms
第三次：1s
后续：2s
最大：5s
```

重新连接成功后必须重新同步完整输入状态。

### 16.3 网络切换

MVP 允许一个设备保存多个 IP：

```toml
ips = [
  "192.168.1.20",
  "192.168.1.21"
]
```

连接时依次尝试。

不得在活跃控制过程中无提示地切换到高延迟链路。

### 16.4 消息类型

协议逻辑上至少包括：

```text
Handshake
AuthorizationRequest
AuthorizationResponse
Heartbeat
HeartbeatAck
InputEvent
InputStateSnapshot
SwitchRequest
SwitchAck
ReleaseAll
Error
Metrics
```

实际实现应尽量复用现有协议。

协议变更必须增加版本号或兼容机制。

## 21. 验收标准

### AC-01 基础连接

Given Windows 与 Mac 位于同一局域网
When 用户在两台设备启动 CrossDesk 并完成授权
Then 双方状态显示为已连接。

### AC-02 Windows 切换到 Mac

Given Mac 被配置在 Windows 右侧
When 鼠标从 Windows 右边缘继续向右移动
Then 鼠标控制进入 Mac，且切换时间 P95 不高于 80ms。

### AC-03 Mac 返回 Windows

Given 当前控制目标为 Mac
When 鼠标从 Mac 左边缘继续向左移动
Then 控制权返回 Windows。

### AC-04 目标离线

Given Mac 当前离线
When 用户把鼠标移动到 Windows 右侧边缘
Then 鼠标不得丢失，本机控制必须正常保留。

### AC-05 按键状态恢复

Given 用户按住 Ctrl 或 Command
When 网络突然断开
Then 本地立即恢复控制，远端在连接恢复后不得继续保持修饰键按下。

### AC-06 鼠标按钮恢复

Given 用户按住鼠标左键
When 接收端程序被强制关闭
Then发送端在 1 秒内恢复本机鼠标，重新连接后远端左键状态为松开。

### AC-07 紧急释放

Given 当前输入正在发送到远端
When 用户按下紧急释放快捷键
Then 控制权立即返回本机，不依赖远端响应。

### AC-08 性能

Given 两台设备通过有线千兆网络连接
When 用户持续移动鼠标 5 分钟
Then输入端到端延迟 P95 不高于 15ms，且事件队列无持续增长。

## 28. 项目优先级原则

项目开发优先级必须始终遵循：

```text
不失控
> 不丢按键状态
> 稳定连接
> 低延迟
> 跨屏手感
> 键位兼容
> 配置体验
> UI 美观
> 扩展功能
```

任何时候，安全恢复能力都优先于极限低延迟。

任何时候，真实可测量的数据都优先于主观判断。

任何时候，最小可验证改动都优先于一次性重写。
